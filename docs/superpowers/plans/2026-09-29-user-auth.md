# Admin User Auth Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Admin dashboard users can sign up, sign in and sign out with email + password; sessions use `has_secure_token`.

**Architecture:** `User` gets `has_secure_password` and `has_secure_token :authentication_token`. Admin API controllers inherit a new `Api::V1::BaseController` that authenticates via the `X-User-Token` header and sets `current_user`. Signup/signin return the token; signout regenerates it. The React dashboard stores the token in localStorage, sends it on every request and redirects to `/admin/login` on 401.

**Tech Stack:** Rails 7 (minitest, FactoryBot), bcrypt, React + react-query + neetoui + formik/yup.

**Spec:** `docs/superpowers/specs/2026-09-29-user-auth-design.md`

## Global Constraints

- Password minimum length: 6.
- Token header: `X-User-Token`. localStorage key: `userToken`.
- Public reader flow (`Api::V1::Public::*`, `X-Auth-Token`, `X-Visitor-Token`) must not change behavior.
- Signup is open (no invitation / first-user restriction).
- Signin failure uses one generic message (`session.incorrect_credentials`) for unknown email and wrong password.
- Signout regenerates the token (one token per user).
- Ruby style: match existing (double quotes, `frozen_string_literal`, private methods indented under `private`).

## Review Focus

- Blank/missing `X-User-Token` must never authenticate, even when legacy users have a `nil` token (`find_by(authentication_token: nil)` would match them).
- Token of a user from a different site must not authenticate on this site.
- Email sign-in is case-insensitive (`email` is `citext`) and scoped to the site.
- Signup with duplicate email in same site, short password, mismatched confirmation → 422 with message, no user created.
- Old token is rejected after signout; signout without a token is 401.
- Action Cable must no longer trust a bare email (`/cable?email=`); it must require the user token.
- Frontend: a 401 from the public (site-password) API must not log the admin out; a 401 from the login form itself must not redirect-loop.

```ruby
# frozen_string_literal: true

module AdminAuthenticatable
  extend ActiveSupport::Concern

  included do
    before_action :authenticate_user_using_x_auth_token
  end

  private

    def current_user
      @_current_user
    end

    def authenticate_user_using_x_auth_token
      token = request.headers["X-User-Token"].presence
      @_current_user = token && @site.users.find_by(authentication_token: token)
      render_error(t("session.could_not_auth"), :unauthorized) unless @_current_user
    end
end
```

class Api::V1::SessionsController < Api::V1::BaseController
  skip_before_action :authenticate_user_using_x_auth_token, only: :create

  def create
    user = @site.users.find_by(email: login_params[:email])
    if user&.authenticate(login_params[:password])

    else
      render_error(t("session.incorrect_credentials"), :unauthorized)
    end
  end

  def destroy

    render_notice(t("session.signed_out"))
  end

  private

    def login_params
      params.require(:login).permit(:email, :password)
    end
end
